# consign 진행 기록

한 일과 그때 배운 것·막힌 것. 새 기록은 표 아래에 한 줄씩 더한다. 실수 카탈로그 항목의 상태는 [CATALOG.md](CATALOG.md) 에서 고친다.

| 날짜 | 한 것 | 배운 것 · 막힌 것 |
|---|---|---|
| 2026-10-27 | 1단계: FastAPI 0.162 · Pydantic 2.14 · SQLAlchemy 2.1 + asyncpg · Postgres 16. 상품 등록·조회·판매·판매자 정산 조회 4개, 테스트 5개 통과 | ① 판매는 **조건부 UPDATE**(`WHERE status='ON_SALE' RETURNING`)로 확인과 변경을 한 문장에 — 동시 20건 중 1건만 201 ② 같은 테스트를 SELECT→검사→변경 순으로 바꾸면 여러 요청이 검사를 통과하고 `sales.item_id` unique 에 막혀 **500(IntegrityError)** — 직접 돌려 확인. unique 는 마지막 방어선이지 정상 경로가 아니다 ③ `expire_on_commit=False` 가 없으면 커밋 뒤 속성 접근이 지연 로딩 → `MissingGreenlet` ④ pytest-asyncio 는 테스트마다 루프가 새로라 `engine.dispose()` 로 풀을 비워야 한다 ⑤ `docker compose up --wait` 직후엔 Postgres 가 아직 초기화 중이라 접속 실패 — `pg_isready` 로 기다림 |
| 2026-10-27 | 연습용 MSA·k8s 환경: consign(판매+Outbox+relay) / settlement(Redis Stream 소비자 그룹, 멱등 원장) 2서비스, 서비스별 DB. kind 클러스터에 각 2 replica + Postgres·Redis, probe·preStop·resources·Secret. 테스트 7개 통과, `make demo` 로 판매 1건이 두 서비스 정산 합계 70,000 으로 일치하는 것 확인 | ① DB 커밋과 메시지 발행을 따로 하면 하나만 성공할 수 있다 → Outbox ② relay 는 at-least-once → 소비자는 PK 로 멱등 ③ ACK 는 DB 커밋 뒤 ④ 앱이 Postgres 보다 먼저 떠서 RESTARTS 2 — k8s 가 재시작으로 수습하지만 과제 1로 남김 ⑤ 연습 과제 8개는 `consign/README.md` |
| 2026-10-28 | 관찰용 콘솔: consign 이 화면 한 장을 내려주고 `/ops/*` 로 Outbox·Redis Stream(XINFO)·정산 원장(서비스 간 HTTP 호출)·판매자별 합계를 모은다. 응답 헤더 `x-served-by` 로 처리 Pod 표시. 테스트 8개 통과, 브라우저에서 동시 20건 → 201×1·409×19, 두 consign Pod 로 9·11건 분산, 두 서비스 합계 일치 확인 | ① 시간대 없는 `timestamp` 에 UTC 가 들어가 화면이 9시간 어긋났다 → `timestamptz` ② 소비자는 Pod 가 사라져도 그룹에 이름이 남는다 → 종료 때 pending 0 이면 `XGROUP DELCONSUMER`(롤링으로 지워지는 것 확인) ③ ASGITransport 는 lifespan 을 안 돌린다 → `lifespan_context` 로 감쌈 ④ 테스트의 기본 정산 주소가 떠 있는 kind 클러스터에 실제로 붙었다 → 테스트는 빈 포트로 ⑤ k8s 가 Service 마다 `SETTLEMENT_PORT` 같은 환경변수를 자동 주입한다 — 설정 이름이 겹치면 오작동할 수 있다 |
| 2026-10-28 | 콘솔 ⓪ 구성도·데이터 흐름: 6개 노드를 선으로 잇고 판매가 감지되면 ①→⑤ 경로로 점이 흐른다. `/ops/topology` 가 실제 접속 대상(postgres:5432/consign · redis:6379 · http://settlement:8000)을 비밀번호 없이 내려준다. 판매 1건 → 5개 노드 순서대로 강조, 여정 표에서 커밋→발행 +0.11s · 발행→원장 +0.01s 확인(이 클러스터·이 1건 값) | 롤링 중엔 종료 중인 settlement Pod 가 잠깐 소비자로 3개 보인다 — 롤아웃 뒤 2개로 돌아오는 것 확인 |
| 2026-10-28 | 연습 과제 8개를 **실수 카탈로그 12건**으로 재구성: 상황→실수, 판매자에게 생기는 일, 콘솔 증상, 해결, 표준 참고. 참고 저장소는 `gh api` 로 존재 확인(fastapi-best-practices ★18k, strong_migrations ★4.4k, rocket-rides-atomic, message-relay, dbos-demo-apps) | 인프라 연습도 "판매자 정산이 어떻게 틀어지나"로 끝맺어야 업무 판단과 이어진다. #7·#8·#12 는 표준 참고를 아직 못 찾았다 |
| 2026-10-29 | 콘솔을 **시나리오 실행기**로 개편(사용자: "시각화·테스트를 시각적으로 확인하기 불편"): 왼쪽 시나리오 3개(단계별 ✅/❌·근거·ms), 오른쪽 구성도 + 상세 탭 5개로 한 화면. 자동 2개 통과, 정산 장애 시나리오는 실제로 settlement 를 0개 → 2개로 바꿔 통과(정산 지연 +31.76s 가 여정 표에 그대로 남음). `make test` 추가 | 테스트를 "터미널 출력"이 아니라 "구성도 옆에서 단계별 판정"으로 보니, 비동기 흐름에서 어느 단계가 얼마나 걸렸는지가 판정과 같이 남는다. 터미널이 필요한 단계도 화면이 결과를 기다려 판정하면 왕복이 줄어든다 |
| 2026-10-29 | 대용량 시나리오 3개(카탈로그 #13~15): 판매 1000건 폭주(outbox 대기·Redis lag·정산 미도착 그래프), 소비자 2→4 전후 비교, 커넥션 풀 고갈. 부하는 서버 안 `/ops/burst`·`/ops/pool` 로 만든다. 테스트 9개 통과, 콘솔 자동 4/4 + 소비자 확장 시나리오 통과. 잰 값(이 kind 클러스터): 판매 1000건 커밋 1,045ms, 정산 마지막 건까지 2.0s / 소비자 2개 1.2s → 4개 1.3s / 300ms 쿼리 100개 → 가장 늦은 2,138ms, 끼어든 SELECT 1 1,776ms | ① 소비자를 늘려도 그대로였다 — 적체가 Redis(lag 30)가 아니라 outbox(343)에 섰다. "느리면 늘린다" 전에 줄이 선 단계를 본다 ② 풀 15개를 넘는 느린 쿼리는 평범한 요청까지 줄 세운다(SELECT 1 이 1.8초) ③ 브라우저 동시 연결 6개 제한 때문에 대용량 부하는 서버 안에서 만들어야 화면 측정이 왜곡되지 않는다 |
| 2026-11-10 | 3b 1단계: RabbitMQ(aio-pika 10.2) 경로를 `BROKER=rabbitmq` 스위치로 추가. relay 는 topic exchange `sales` 에 persistent 메시지로 발행(publisher confirm), settlement 는 durable 큐 `settlement.sales` 를 prefetch 10·manual ack(DB 커밋 뒤)로 소비. compose·k8s 에 RabbitMQ 추가. 테스트 11개 통과(새로 2개: exchange 발행, 중복 메시지 → 원장 1건), 로컬 두 프로세스로 판매 3건 → 두 서비스 합계 210,000 일치. kind 가 설치돼 있지 않아 클러스터 배포는 `kubectl kustomize` 렌더링까지만 확인 | ① `connect_robust` 는 붙은 뒤 끊긴 연결만 복구한다. 첫 연결 실패는 직접 재시도해야 앱이 브로커보다 먼저 떠도 relay·소비자가 조용히 죽지 않는다 ② 그 재시도 때문에 브로커 없이 pytest 를 돌리면 멈춘다 → 테스트는 5초 안에 연결을 확인하고 실패시킨다 ③ 관리 UI 포트 15672 가 다른 프로젝트 브로커와 겹쳐 compose 가 뜨지 못했다 → 55673 ④ `message.process()` 는 예외가 나면 기본으로 requeue 없이 reject 해 메시지를 버린다. 그래서 커밋 뒤 `ack()` 를 직접 부른다 ⑤ 실패는 지금 1초 뒤 바로 requeue 한다(#18 의 실수 그대로). 3단계에서 고친다 ⑥ `test_settlement` 이 정산 DB 에 sale_id 1 을 남겨 e2e 첫 판매가 "중복 무시"로 보였다. 멱등 키는 맞게 동작했지만 테스트 데이터가 서로 새는 문제다 |
